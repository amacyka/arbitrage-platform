# Crypto Arbitrage Intelligence Platform

Мониторинг и поиск потенциальных арбитражных возможностей между
криптобиржами. **Этап 1 (MVP): Binance ↔ Bybit.** Реальные сделки нигде
не совершаются — только анализ, сигналы в Telegram и виртуальная
(paper trading) торговля.

Полный анализ идеи, архитектура и план развития (этапы 2–6: добавление
Хрокета и Крипто Бота) — в отдельном документе с ТЗ.

## Что уже работает (Этап 1)

- Сбор котировок с публичных REST API Binance и Bybit (без ключей).
- Нормализация в единый формат.
- Расчёт спреда, комиссий, приблизительного проскальзывания, ROI —
  для всех направлений (Binance→Bybit и Bybit→Binance).
- Фильтрация сигналов по минимальному ROI / прибыли / объёму.
- Telegram-бот: `/start`, `/settings`, `/set_roi`, `/set_profit`,
  `/set_volume`, `/stats`, кнопки меню («Найти возможности», «Рынок»,
  «Активные сигналы», «Paper Trading»).
- Paper Trading: виртуальный баланс 10 000 USDT, открытие/закрытие
  виртуальных сделок по сигналу.
- Простой HTTP API (`/api/market`, `/api/signals`) для отладки и будущего
  веб-дашборда.

## Важные оговорки (честно, без придумывания)

- **Комиссии** (`BINANCE_TAKER_FEE`, `BYBIT_TAKER_FEE`) — это
  сконфигурированные значения по умолчанию (стандартные ставки без
  скидок), а не то, что реально прочитано с вашего аккаунта. Точная
  комиссия зависит от вашего тарифа/скидок и требует авторизованного
  запроса, который MVP намеренно не делает.
- **Проскальзывание** считается по упрощённой модели (см. комментарий в
  `app/engine/risk.py`), а не по реальной глубине стакана — Bybit/Binance
  тикер-эндпоинты дают только лучший bid/ask, не полный стакан.
- **Список торгуемых активов** (`TRACKED_ASSETS`) — стартовый набор
  (BTC, ETH, SOL, BNB, XRP, TON, DOGE к USDT). Коллекторы сами проверяют
  через `exchangeInfo` / `instruments-info`, какие пары реально существуют,
  и пропускают то, чего нет — ничего не выдумывается на лету.
- **Хрокет и Крипто Бот** в этот код пока не входят — это этапы 2–5 по
  плану в документе с ТЗ.

## Структура проекта

```
app/
  config.py              # настройки (.env)
  normalizer.py           # единый формат котировки
  database/
    models.py             # MarketSnapshot, ArbitrageSignal, PaperTrade, UserSettings
    db.py
  exchanges/
    binance.py             # read-only REST клиент Binance
    bybit.py                # read-only REST клиент Bybit
  collectors/
    binance_collector.py   # фоновый опрос Binance
    bybit_collector.py      # фоновый опрос Bybit
  engine/
    risk.py                 # формулы: спред, комиссии, проскальзывание, ROI
    arbitrage.py             # сравнение всех направлений между источниками
    scanner.py                # цикл сканирования + антидубли + рассылка сигналов
  bot/
    handlers.py               # aiogram-хендлеры (/start, /settings, меню)
    formatting.py               # формат алерта в Telegram
    notifier.py                  # подписка на сигналы сканера -> отправка в чаты
  paper_trading.py            # виртуальный баланс и виртуальные сделки
  web.py                        # FastAPI: HTTP API + запуск фоновых задач (для Render)
  main.py                        # альтернативный отдельный процесс бота (без веб-слоя)
```

## Локальный запуск (Docker Compose)

1. Скопируйте `.env.example` в `.env` и при желании впишите
   `TELEGRAM_BOT_TOKEN` (без токена всё, кроме бота, всё равно работает —
   сбор данных и расчёт сигналов идёт в фоне).
2. `docker compose up --build`
3. Проверить, что сервис поднялся: `http://localhost:8000/api/market`

## Деплой на Render (бесплатный план, как в прошлом проекте)

`render.yaml` уже описывает единый `web`-сервис (без отдельного worker —
бесплатный план Render его не поддерживает), который держит внутри себя
и HTTP API, и сборщики данных, и Telegram-бота. Шаги — как в
crypto-liquidity-monitor: New → Blueprint → указать репозиторий → в
поле `TELEGRAM_BOT_TOKEN` вписать токен бота от @BotFather → Apply.

## Следующие шаги

Код кода не начинать без вашей команды — этот коммит покрывает только
Этап 1 (Binance ↔ Bybit). Этапы 2–6 (добавление Хрокета и Крипто Бота,
полная матрица из 12 направлений) описаны в документе с ТЗ и требуют
отдельного подтверждённого способа получения данных для каждого из этих
двух источников, прежде чем писать соответствующие коллекторы.
